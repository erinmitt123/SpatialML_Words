## Differences from B
- Model target: **GPU** for YOLOX-M, as PICO advised on 2026-10-29 (the postprocess model stays on CPU, as in B). `--target cpu` is still available for diagnostics, but it runs ~2.5–3 s per frame.
- App id `com.wordworld.app`, product name `WordWorld` (the samples app is not overwritten).
- Only the 37 household classes from CLAUDE.md are tracked; others are shown greyed in the debug panel and ignored.
- Coordinates: OpenXR right-handed → Unity by negating z.
- Depth: B's live mode uses the room mesh only. Word World keeps B's original stereo branch too, because the mesh is not available in Unity Spatial mode yet (see blockers). Stereo depth verified on Swan 2026-10-29 (steady ~2.1 m on a static target).
- Tracker: Word World follows CLAUDE.md section 2, with two pieces of B's `YoloWorldTracker`: global Hungarian matching (`YoloObjectAssignment` → `Tracking/ObjectAssignment.cs`) and, for confirmed objects only, B's camera-aware re-acquisition gate and footprint checks (`YoloObjectGeometry.score` → `Tracking/ObjectGeometry.cs`). New candidates still need 5 of 8 frames within 0.25 m. Not ported: B's ambiguity witnesses (cannot-merge pairs), multi-view ray relocalisation (`YoloRayLocalization`), alias consolidation and per-track variance.
- Packet rows: NMS output is fixed-size, and on Swan its trailing slots are padding that points at suppressed candidates (overlapping copies of real detections) with an NMS score of 1.0 or 0.0. That padding made duplicate and phantom objects. The packing script keeps only slots whose NMS score equals the candidate score, each candidate once (verified 2026-10-29: bed + tv gives exactly 2 confirmed objects). Lanes 17-18 carry the candidate index and NMS score for the development-build `raw slots` log.
- Text: labels and the debug panel use `SpatialAdapterNativeText` (drawn by the Spatial Engine). TextMeshPro text rendered as solid blocks on Swan.

## Blockers found on Swan (2026-10-29)
- **YOLOX-M on GPU: works, but only on a clean SecureMR service** (fixed 2026-10-29). On a freshly rebooted Swan,
  YOLOX-M at 640 loads in ~2 s and runs ~50 ms per inference; Word World runs at ~7.4 Hz steady.
  Once any GPU model fails to load (`LiteRt create input buffer failed`), *every* later GPU load fails, even PICO's
  3-node face preprocess, until Swan is rebooted. Running the face GPU sample first also left too little GPU memory for YOLOX.
  If the detector logs that error: reboot the headset, then run Word World without other SpatialML apps first. Tell PICO
  (the service seems not to free GPU state when a session ends or a model fails).
  Tested and *not* needed: UINT8 input, FP32 weights, 320 input (all also work on a clean service; UINT8 640 is ~50 ms too).
- **NPU:** still fails (`NPU accelerator could not be loaded and registered`).
- **Room mesh in Spatial mode:** `PXR_Loader` only creates "PICO Mesh" under AR Foundation 6, so `RoomMesh` creates it.
  Two descriptors share that id; PxrPlatform's returns null (library not loaded in Spatial mode) and StagePlatform's works.
  The native `MeshTrackingManager` (the same C++ tracker the sample's Kotlin API wraps) reaches RUNNING, but no data
  reaches Unity: no MESH_UPDATE events and `TryGetMeshInfos` stays false over 75 s. Ask PICO what else the
  Spatial-mode mesh needs. Placement uses stereo depth meanwhile.
- **App container:** the build used the Constrained camera config (a 2.5 m volume), so content was confined to a window.
  It now uses the Unconstrained config (a stage, like the sample's `pico.spatial.stage.*` activity).

## Open questions
1. **Colour order.** B feeds RGB 0–255 with no normalisation; YOLOX is usually trained on BGR. Check with PICO which their export expects (CLAUDE.md §2 requires this to match).
2. Letterbox: confirm the pipeline letterboxes the 640 input rather than stretching.
3. Does the frame counter persist between runs? The detector handles either case.
4. Runtime-created meshes may not render in Spatial mode, so the room mesh debug view is best-effort (colliders work regardless).
5. Spatial anchors in Spatial mode: API not yet identified; labels are world-locked without them for now.
6. Licence: the YOLOX-M model is for prototyping only; swap in an Apache-2.0 model before release via `IObjectDetector`.
